# Gift deploy checklist

The app is three pieces: **Supabase** (Postgres database), **Render** (Django API, `render.yaml`) and **Vercel** (React frontend). AI runs only inside Django. The browser never sees an AI key.

Work through the sections in order, then run the [smoke test](#smoke-test) as a brand-new account before handing the app over.

## 0. Before anything: rotate the database password

Old docs in this public repository contained the Supabase database password. They are deleted now, but the password is still in the git history. In Supabase go to **Project Settings → Database → Reset database password**, then put the new connection string into Render's `DATABASE_URL` (step 2).

## 1. Supabase (database)

- Use the **Session pooler** connection string (port 5432) from **Project Settings → Database → Connection string**.
- URL-encode special characters in the password (`#` → `%23`, `@` → `%40`).
- Nothing else to do here. Django creates and updates the tables itself (step 2).

## 2. Render (backend)

Create the service from the blueprint (`render.yaml`). If the service already exists, copy its settings by hand:

| Setting | Value |
|---|---|
| Build command | `pip install -r backend/requirements.txt` |
| Start command | `cd backend && python manage.py migrate --noinput && gunicorn exam_app.wsgi:application --bind 0.0.0.0:$PORT --timeout 120` |
| Health check path | `/api/` |

**Migrations run on every start** through the start command, because Render's free plan has no pre-deploy hook. If the service was created before this change, update its start command in the dashboard. Otherwise new tables (study docs, study chats, attempt de-duplication) are never created. In the deploy logs, look for `Applying api.000X…` or `No migrations to apply`.

Environment variables:

| Variable | Required | Value |
|---|---|---|
| `DATABASE_URL` | yes | Supabase connection string from step 1 |
| `SECRET_KEY` | yes | Auto-generated by the blueprint; any long random string otherwise |
| `DEBUG` | yes | `False` |
| `FRONTEND_URL` | yes | The exact Vercel origin, e.g. `https://my-exit-prep.vercel.app` (no trailing slash). This is the only allowed CORS origin besides localhost. |
| `AI_API_KEY` | for AI features | API key of an OpenAI-compatible provider (e.g. xAI) |
| `AI_MODEL` | for AI features | A model that accepts **image input**, needed for scanned exam PDFs and study-doc descriptions |
| `AI_BASE_URL` | optional | Defaults to `https://api.x.ai/v1` |
| `AI_TIMEOUT_SECONDS`, `AI_MAX_TOKENS` | optional | Defaults `180`, `8192` |
| `EXAM_IMPORT_MAX_PAGES`, `EXAM_IMPORT_MAX_UPLOAD_MB`, `STUDY_DOC_MAX_PAGES`, `STUDY_DOC_MAX_UPLOAD_MB` | optional | Defaults `60`, `25`, `400`, `25` |
| `ALLOWED_HOSTS` | no | Not read; the settings accept any host |

Without `AI_API_KEY` / `AI_MODEL` the app still works: exams, practice, plans, JSON import, uploads. The AI features show a clear "not configured" message.

**Check:** `https://<your-render-service>.onrender.com/api/` returns a JSON list of endpoints.

## 3. Vercel (frontend)

- Framework: Vite (`vercel.json` already sets the build and SPA rewrites).
- Environment variable: **`VITE_API_BASE_URL`** = `https://<your-render-service>.onrender.com/api` (no trailing slash). This is the **only** frontend variable. Never add AI keys or other secrets with a `VITE_` prefix, because they are baked into public JavaScript.
- Vite reads the variable at **build** time, so redeploy after changing it. If it is unset, the build falls back to `https://exit-exam-backend-qii8.onrender.com/api`.

## 4. Storage limits (read this)

Uploaded PDFs are stored on the Render instance's local disk (`MEDIA_ROOT`). On the free plan that disk is **ephemeral**: it is wiped whenever the service redeploys, restarts, or spins down after ~15 minutes idle. No Supabase Storage / S3 integration exists yet.

- **Exam PDF import:** finish extraction in one sitting. Drafts and published exams are in the database and are safe. If the file disappears mid-extraction, upload the PDF again. The PDF is deleted after publishing anyway.
- **Study materials:** each doc's AI description, topics, key points and text excerpt are in the database. **Study chat keeps using them after the file is gone.** Download and "Retry description" need the file, so upload it again for those. The card says when the file is no longer stored.

## 5. Accounts

Nobody needs an admin account. The giftee opens the Vercel URL and signs up. Each account sees only its own exams, questions, attempts, plans, study materials and chats.

## Smoke test

Run this on the deployed URLs with a **fresh account**. Sample files are in `data/`.

1. **Cold start:** open the Vercel URL after the backend has been idle for 15+ minutes. Expect a yellow "Waking up the server…" banner; within about a minute the login page works.
2. **Register / log in:** sign up with a username and password. You land on the Dashboard, which shows a "Welcome! Three steps to get started" card and empty stats.
3. **Upload a study PDF:** go to **Study** → *Choose PDFs* → `data/sample-study-notes.pdf`. Within ~30 s the card shows a short description, the subject *Database Systems*, and topics such as *Normalization*.
4. **Create an exam from a PDF:** go to **Exams** → *Create* → **From PDF** → `data/sample-exam-photo.pdf` (image-only, like phone photos). Wait for both pages, review the 6 questions, then *Publish*.
   - **JSON fallback** (no AI): **From JSON** → `testQuestions.json`.
5. **Take the exam:** start it, answer a question, press *Show Answer*, then ✨. The Study tutor opens for that question's topic, which proves the server AI path. Finish the exam. Results appear, and Analytics counts each answer once.
6. **Study from the planner:** go to **Plan** → **Study these topics** → *Start lesson*.
   - Expect "Chunk 1 of 4" ending with **Memory Lock**, **Exam Traps** and **Likely Questions**, and a request to say "continue".
   - If your study notes match the day's topics, the header lists them under "Using your materials".
   - Press **Continue** and you get Chunk 2. Refresh the page; the conversation is still there and is also listed under **Study**.
   - The day's focus subject comes from Plan Manager priorities. If the bank has no questions for it yet, the plan says so; the Study button still works.
7. **Privacy:** log out, sign up a second account. It sees an empty dashboard, and none of the first account's exams, docs or chats.

## Still manual before gifting

- [ ] Rotate the Supabase password (step 0) and update `DATABASE_URL` on Render.
- [ ] Set `AI_API_KEY` and `AI_MODEL` (vision-capable) on Render, and `FRONTEND_URL` to the Vercel origin.
- [ ] Make sure the Render start command includes `python manage.py migrate --noinput`.
- [ ] Set `VITE_API_BASE_URL` on Vercel and redeploy.
- [ ] Run the smoke test above.
- [ ] Merge `dev-v0.2` → `main` (a human step after the smoke test passes), and confirm Render and Vercel deploy from the branch you expect.

## Troubleshooting

- **Browser console shows a CORS error:** `FRONTEND_URL` on Render does not exactly match the Vercel origin (scheme, no trailing slash). Preview deployments on other `*.vercel.app` URLs are not allowed.
- **"…not configured on the server (AI_API_KEY / AI_MODEL)":** set both on Render and redeploy.
- **AI errors mentioning the model:** `AI_MODEL` is wrong for the provider at `AI_BASE_URL`, or the model has no image input.
- **"Can't reach the server":** the backend is asleep or failed to boot. Check the Render logs (a failed migration shows there) and press *Retry*.
